# Сайт Dr. Alybaev

Next.js 16 (App Router, Turbopack) · React 19 · TypeScript strict · Tailwind v4.

Требования: Node 20+, pnpm. Установка: `pnpm install`.

Команды: `dev`, `build`, `start`, `lint`, `typecheck`, `format`, `test`, `analyze`.

Архитектура — FSD в `src/`: `app → widgets → features → entities → shared`,
импорт разрешён только вниз по цепочке (правило `import/no-restricted-paths`).
`content` — слой данных, без логики.

Дизайн-токены — единственный источник правды: блок `@theme` в `src/app/globals.css`.

## Админка

Панель находится на `/admin`. Демо: `/admin?demo=1`. В демо изменения сохраняются только
в браузере, не меняют файлы проекта и не публикуются. В рабочей панели врач входит по
email и паролю, редактирует 15 разделов, загружает фото, добавляет и переставляет
карточки работ, отзывы, сертификаты, услуги, FAQ и этапы восстановления.

Сайт и панель работают на Netlify без отдельного сервера. Netlify Identity отвечает
за вход, Next.js Route Handlers работают в серверных функциях Netlify. Сохранение
изменяет JSON в GitHub и запускает автоматическую сборку сайта. Git Gateway не используется.

### Подключение на Netlify

1. Подключите существующий проект `alybaev` к репозиторию `buranJ/alybaev`, ветке `main`.
   Включите автоматическую публикацию. Команда сборки `pnpm build`, папка `.next`;
   эти параметры уже записаны в `netlify.toml`.
2. В разделе **Identity** включите сервис и установите регистрацию **Invite only**.
   Пригласите email врача/администратора. Открытая регистрация в панели не предусмотрена.
3. Добавьте серверные переменные окружения (scope **Functions**, не `NEXT_PUBLIC_`):
   - `ADMIN_EMAILS` — разрешённые email через запятую;
   - `GITHUB_CONTENT_TOKEN` — fine-grained GitHub token только для `buranJ/alybaev`,
     с разрешением **Contents: Read and write**;
   - `NETLIFY_IDENTITY_URL` — `https://alybaev.netlify.app/.netlify/identity`.
     При смене Identity-сайта обновите адрес.
4. Выполните деплой после добавления переменных. Письмо приглашения возвращает человека
   на сайт; он автоматически открывает `/admin`, где человек самостоятельно создаёт пароль.
   Восстановление пароля также обрабатывается панелью.
5. Проверьте вход приглашённого человека, добавление фото и сохранение одного раздела.
   Изменения появятся на публичном сайте после успешной сборки Netlify.

Администратору не нужен аккаунт GitHub или Netlify. Он не видит серверный токен.
Каждый запрос проверяет действительность сессии у Netlify Identity и разрешённый email.
Сохранение использует версию файла: если другой редактор успел поменять раздел,
панель откажется перезаписывать его. Чтобы обновить, выберите другой раздел и вернитесь.

Фото принимаются в JPG, PNG, WebP или AVIF до 5 МБ, автоматически уменьшаются до
2000 пикселей, конвертируются в WebP и очищаются от метаданных. SVG можно выбрать
из существующих файлов для логотипа; загрузка новых SVG запрещена. Загрузка фото
не запускает отдельную сборку: оно публикуется вместе со следующим сохранением раздела.
Видео размещаются по ссылке на YouTube, а не загружаются в Git.

### Разработка

`pnpm dev` запускает сайт и панель на `http://localhost:3000`. Демо работает без
секретов и авторизации. Для реального входа локально нужен `netlify dev` с настроенным
Identity; простого `next dev` недостаточно для Identity API.

Редактируемые данные находятся в `content/*.json`. Схемы Zod проверяют их при сборке
и при сохранении через API. `pnpm cms:config` создаёт описание русскоязычных полей
в `public/admin/config.json`; генерация запускается и перед `pnpm build`.
Размеры и расположение блоков задаются компонентами сайта, а не редактором контента.

Проверки: `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`.

Документация: [Netlify Identity](https://docs.netlify.com/manage/security/secure-access-to-sites/identity/overview/),
[сборки из Git](https://docs.netlify.com/deploy/create-deploys/),
[GitHub Contents API](https://docs.github.com/en/rest/repos/contents).
